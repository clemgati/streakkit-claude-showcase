## Your task

The matrix above is generated by the local MCP server and covers the two kinds of drift a tool
can detect by itself:

- an `expect` with a missing `actual` (the build catches this, but only for the platform you built);
- a shared UI-state field that one app renders and the other silently ignores (nothing catches this).

Your job is the third kind, which needs judgement: **the two apps render the same field but mean
different things by it.**

Check these specifically, reading both implementations side by side:

1. `androidApp/.../ui/HabitCard.kt` vs `iosApp/StreakKit/Views/HabitCardView.swift` — is the
   streak label built from the same fields, in the same order, with the same empty/broken-streak
   wording?
2. The week strip in both — same number of cells, same today-marker, same tap target (whole cell
   vs. circle only)?
3. The completion percentage — same rounding? One using `roundToInt` and the other truncating is
   a real defect that produces a 1% difference users notice.
4. Any formatting done in a view rather than in `summarize()`. That is the root cause of almost
   all drift: formatting belongs in the shared module precisely so it cannot diverge.

$ARGUMENTS

Report as a short table: *aspect · Android · iOS · verdict*. For anything that differs, state
which side is wrong and why, and propose the fix in `commonMain` rather than in both views.
End with a one-line verdict: safe to ship, or not.
